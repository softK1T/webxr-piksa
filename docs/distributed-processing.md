# Исследование распределённой обработки

## Задачи, которые можно распределить
| Задача | Сейчас | Возможный вариант |
|---|---|---|
| Генерация 15 моделей в Blender | Последовательно, headless, секунды | Пул процессов `blender --background` по одному на генератор |
| Валидация GLB | Синхронно в API при загрузке | Очередь (Redis + RQ/Celery) для больших файлов |
| Построение LOD / сжатие (Draco, meshopt) | Не требуется | Воркеры в CI или на сервере |
| Рендер в VR | Локально на шлеме | Cloud XR-стриминг — не подходит для WebXR из-за задержки |

## Оценка
- Модели лёгкие (до 7 000 треугольников), генерация и валидация выполняются локально за секунды.
- Для рендера в VR сетевая задержка критична (motion-to-photon < 20 мс), поэтому рендер остаётся на устройстве.

## Вывод
Отдельная распределённая платформа не нужна. При росте числа моделей первый шаг — параллельный запуск генераторов в `generate_all.py` и фоновая очередь для валидации загруженных GLB.

## Реализовано
| Мера | Где | Эффект |
|---|---|---|
| Параллельная загрузка моделей (до 6 одновременно) | `apps/web/src/scene/loadLabModels.ts`, `mapLimit` | Сцена собирается быстрее, чем при загрузке по одной |
| Несколько процессов API (`uvicorn --workers`, `API_WORKERS`, по умолчанию 2) | `apps/api/Dockerfile`, `docker-compose.yml` | Запросы обрабатываются параллельно на разных ядрах |
| Сессии без состояния (подписанные cookie) | `apps/api/app/auth.py` | Любой процесс или экземпляр API обслуживает любого пользователя, можно ставить за балансировщик |
| Сжатие ответов GZip и кэш моделей в браузере (сутки) | `apps/api/app/main.py` | Меньше трафика, повторный вход не скачивает GLB заново |
| Рендер на устройстве, LOD и профили качества | `apps/web/src/scene/quality.ts` | Нет сетевой задержки в кадре (motion-to-photon) |
